# Задание 3. Оценка Data Encryption at Rest and In Transit

|Данные | В чём необходимость защиты | Инструменты защиты |
|-------|----------------------------|--------------------|
|PII (ФИО, паспортные данные и тд)| 152-ФЗ |AES-256 шифрование в хранилищах (at rest), TLS 1.3 при передаче, токенизация, контроль доступа RBAC|
|Медицинские данные| Утечка данных несет репутационные и юридические ущербы | AES-256 шифрование в базах данных и файловых хранилищах, TLS 1.3, электронная подпись для гарантии целостности|
| Финансовые транзакции | Финансовые данные подвержены | Шифрование в СУБД, TLS 1.3, HSM для хранения ключей|

## Использовать автоматизированный контроль. 
1. Контроль доступа
    - API Gateway: единая точка
    - Keycloak: Аутентификация, Active Directory
    - Проверка информированного согласия
2. Аудит и мониторинг
    - ElasticSearch: логирование сервисов без ПДн
    - Prometheus, Grafana
    - SIEM

## Реестр программных и аппаратных средств для защиты данных.
  - PostgreSQL Encryption: защита данных в базе данных PostgreSQL.
  - TLS 1.3: защищённая передача данных по сети.
  - Keycloak: управление идентификацией и доступом (IAM).
  - Apache Kafka: распределённая платформа для потоковой обработки данных.
  - ElasticSearch: поисковая и аналитическая система.
  - Vault: безопасное управление секретами и шифрованием.
  - API Gateway: единая точка входа для API‑сервисов.
  - SIEM: система мониторинга и реагирования на инциденты ИБ.
